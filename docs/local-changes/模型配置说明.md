# AgentScope Service 里怎么配置模型

> 适用：main 分支新版控制台（http://localhost:18080）
> 实测时间：2026-09-14，已跑通一轮真实 DeepSeek 对话

## 一图看懂：模型配置分三层

| 层级 | 在哪配 | 作用范围 | 是否常用 |
| --- | --- | --- | --- |
| **Agent 级** | 控制台：Design → Agents → 选中 Agent → **Behavior** 卡片 → **Model** | 这个 Agent 的所有会话 | ✅ 最常用 |
| **创建时指定** | Design → Agents → 新建 Agent 表单里的 **Model** | 同上 | ✅ |
| **全局默认** | Dataplane 配置：`application.yml` 的 `builder.dashscope.*` / 环境变量 | Agent 没填 model 时兜底 | ⚪ 兜底 |

**关键区分：模型 id 在控制台配，API Key 不在控制台配。**
Key 是 Dataplane 进程的环境变量，改 key 必须重启 Dataplane。

## 二、Agent 级（控制台操作，推荐）

路径：**Design → Agents → 点进某个 Agent → Behavior 卡片 → Model 输入框**

输入框里填的是 **`provider:model` 格式的模型 id**，界面上给的示例原文是：

```
e.g. dashscope:qwen-max, deepseek:deepseek-chat, openai:gpt-4o
```

旁边的说明文字：

> Provider-qualified model id resolved via ModelRegistry;
> empty falls back to the data-plane default model.

对应源码：`frontend/src/components/AgentSettingsForm.tsx:285`

创建 Agent 时也有这个字段（`frontend/src/pages/AgentCreatePage.tsx:266`），
提示是 "Optional override. Leave blank to use the runtime provider's default model."

填写后会写进 Agent 定义的 `definition.model`，落库字段与
`HarnessAgentBuildService` 里的 `snapshot.model()` 对应；运行时走
`ModelRegistry.resolve(modelId)` 找到对应 provider。

## 三、全局默认（Dataplane 配置）

配置文件：`agentscope-service/service-dataplane/src/main/resources/application.yml`

```yaml
builder:
  dashscope:
    api-key: ${DASHSCOPE_API_KEY:}
    model-name: ${BUILDER_MODEL_NAME:${CLAW_MODEL_NAME:qwen-max}}
    stream: true
```

对应环境变量：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `DASHSCOPE_API_KEY` | 全局默认模型的凭据 | 空 |
| `BUILDER_MODEL_NAME` | 全局默认模型名 | `qwen-max` |

源码里是 `@ConditionalOnMissingBean(Model.class)`：只有没有任何其他 `Model` bean 时才创建这个
DashScope 默认模型，且 Agent 没指定 model 时才回落到它（`HarnessAgentBuildService`：
`if (modelName != null) b.model(modelName); else if (model != null) b.model(model);`）。

## 四、当前这套已注册的 provider（可直接填的 model 前缀）

从正在运行的 dataplane jar 里的 SPI 注册文件读出来的：

| model id 前缀 | Provider | 需要的环境变量 | 默认 base URL |
| --- | --- | --- | --- |
| `dashscope:` | 阿里云 DashScope | `DASHSCOPE_API_KEY` | 阿里云 |
| `deepseek:` | DeepSeek | `DEEPSEEK_API_KEY` | https://api.deepseek.com |
| `openai:` | OpenAI | `OPENAI_API_KEY` | https://api.openai.com |
| `kimi:` | Moonshot Kimi | `KIMI_API_KEY` 或 `MOONSHOT_API_KEY` | https://api.moonshot.cn/v1 |
| `glm:` | 智谱 GLM | `ZAI_API_KEY` / `GLM_API_KEY` / `ZHIPUAI_API_KEY` | https://open.bigmodel.cn/api/paas/v4 |
| `minimax:` | MiniMax | `MINIMAX_API_KEY` | https://api.minimaxi.com/v1 |

用法举例：`deepseek:deepseek-chat`、`deepseek:deepseek-reasoner`、`openai:gpt-4o`、`kimi:moonshot-v1-8k`。

## 五、换 Key / 换 Provider 的完整步骤

1. 写 key（放进本地文件，start.sh 会自动加载）：

```bash
echo 'export DEEPSEEK_API_KEY=sk-你的key' > ~/.deepseek-key
chmod 600 ~/.deepseek-key
```

2. 重启栈（让 Dataplane 进程带上环境变量）：

```bash
cd "/Users/sun7788/Documents/Codex/AgentScope学习笔记/05-新版控制台-main分支"
./scripts/start.sh
```

3. 在控制台把 Agent 的 Model 填成 `deepseek:deepseek-chat`（或创建 Agent 时填）。

## 六、实测证据（真实调用成功）

用 `deepseek:deepseek-chat` 建 Agent 并对话，会话事件流如下：

```text
user.message: "用一句话介绍你自己，并说明你是什么模型。"
session.status_running
span.model_request_start
span.model_request_end
agent.message: "我是 DeepSeek 助手，一个帮你处理代码与工作区任务的简洁中文 AI 助理；底层模型是 DeepSeek。"
session.status_idle
```

说明整条链路（控制台 → aistiod → Dataplane → ReActAgent → DeepSeek API）已打通。

## 七、一个易踩的坑：managed Agent 必须带 definition

用 API 创建「AgentScope 托管」类型的 Agent 时，只传 `binding.kind=managed` 会失败：

```json
{"error":"managed Agent requires definition"}
```

必须同时给 `definition`（控制台表单会自动带上）：

```bash
curl -X POST "http://localhost:18080/api/v1/agents?tenant=default&namespace=default" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
    "agentKey": "deepseek-managed",
    "name": "DeepSeek 助手",
    "binding": {"kind": "managed"},
    "definition": {
      "name": "DeepSeek 助手",
      "model": "deepseek:deepseek-chat",
      "system": "你是简洁的中文助手。",
      "maxIters": 10
    }
  }'
```

成功返回 `"status":"active"`；之后 `/api/v1/chat-agents` 就能看到它，
再用 `POST /api/v1/chats` + `POST /api/v1/chats/{id}/turns` 对话。

> 注意：`tenant` 是 `default`（不是 `admin`），写错会返回
> `"resource not found in authorized scope"`。
